# OPC Agent v1.0.10

本版把升级失败的提示从「猜」变成「实测」，并给每次交换留下分阶段证据。

## 修复

- **更新失败提示改成实测口径**：不再只报一个固定预算。现在会写成「已等待 20.0 秒（预算 60 秒）」——前半是这次真实经过的时长，后半才是预算，两者分开。等进程退出阶段失败会点名「等进程退出失败」，抢锁阶段失败会点名「抢锁失败」，卡在哪一步一眼就能看出来。

## 改进

- **分阶段 trace**：`apply-state.json` 新增 `trace`，记录父进程等待耗时、安装目录残留进程等待（出现了哪些 pid、等待后定向结束了哪些）、抢锁耗时（总尝试次数、末次重试间隔、每次重试的 `{dtMs, code}` 采样）与总耗时。成功路径也会写入实测耗时，方便事后判断「这次为什么快 / 慢」。
- **采样有上限**：逐次重试采样按「首 10 条 + 每 10 条留 1 条 + 末 10 条」压缩，最多 50 条；状态文件过大时优先截断 trace，而不是写出半截 JSON。
- **时长只认单调时钟**：所有耗时用 `performance.now` / `hrtime`，系统时间被 NTP 回拨也不会让预算变成负数，或把「已等待」写成谎话；墙钟只用于 ISO 时间戳。

## 校验

- `verify:a176-update-swap` **125 条全过**，新增 6 组假时钟用例：59.9 秒成功 / 60.1 秒失败、文案秒数与实测相差不超过 0.2 秒、系统时间倒退不影响结果与文案、240 次重试的 `attempts` 与末次 `dtMs`、采样不超上限且首末采样正确、setup 与抢锁两个阶段文案可区分。全部用假时钟，不真等预算。
- `verify:a171-update` **195 条全过**。

## 需要注意

- **1.0.9 及更早版本升级仍可能受旧 helper 影响**：旧版内置的是旧交换逻辑与旧文案。若升级失败，请先完全退出应用（托盘退出，并在任务管理器确认没有 `OPC Agent` 进程）再重试；仍不行就用手动包覆盖。
- 新的计时与 trace 随本版 helper 生效，对**之后**的更新才有意义。

## 升级方式

- **1.0.9**：设置 → 关于与隐私 → 检查更新 → 下载更新 → 退出并重启，走应用内自动替换；被残留进程挡住时先完全退出应用再重试，或改用手动包。
- **1.0.8 及更早（含 1.0.7、1.0.6、1.0.5）**：建议手动升一次 —— 完全退出应用（托盘退出，任务管理器确认没有 `OPC Agent` 进程），用本 Release 的 `OPC-Agent-1.0.10-x64-full.zip` 解压覆盖安装目录即可；也可以只把 `resources/app.asar` 换成 Release 里的 `app-1.0.10.asar`（更省流量）。
- **1.0.0 旧版**：内置公钥与当前签名不匹配，需先按上一条手动更新一次。
- 会话数据保存在 `%APPDATA%\opc-agent`，覆盖安装不受影响。
