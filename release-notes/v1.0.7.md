# OPC Agent v1.0.7

本版修掉「应用内更新下载成功、重启后却还是旧版本」的根因，并让失败不再静默。

## 修复

- **应用内更新可以真正换上新版本了**：点「退出并重启」时，旧进程（含渲染、
  GPU 等子进程）往往还没完全退出，它们仍打开着 `resources/app.asar`。旧逻辑
  一退出就立刻改名替换，撞上 `EBUSY`（文件被占用）只试一次就放弃，然后把旧
  版本重新拉起来 —— 用户看到的就是「重启了，版本号没变」。
  现在改为**每 250 毫秒重试、最多等 20 秒**，等文件锁自然释放后再交换；确实等
  不到才判失败，并写明原因。
- **升级失败不再静默**：交接失败（`apply-failed`）或健康检查失败后已回滚
  （`rollback`）的提示，会常驻在「关于与隐私」的更新卡片上，与「发现新版本」
  「下载更新」并排显示；只有你主动点「下载更新」重试时它才会消失，不会再被
  启动 5 秒后的自动检查悄悄清掉。
- **失败原因说清楚**：错误提示会带上没装上的版本号，以及「旧版本文件仍被占用
  （EBUSY），可能还有 OPC Agent 进程没有退干净（已等待 N 秒）」这类成因，并
  给出「重新下载重试 / 关闭所有窗口后重试 / 手动下载完整包」三条出路。

## 校验

- 验收主链扩到 **99 段**，新增 `verify:a176-update-swap`（本轮 **20/20 通过**）。
  它在临时目录里用假 `app.asar`、假 helper、假 app 真跑三条路径：
  交换成功（含 2.5 秒文件占用）、健康超时自动回滚、持续占用超预算显式失败；
  目录名带空格与中文，顺带覆盖路径含空格。

## 需要注意

- **1.0.5 及更早版本（包括已经发布的 1.0.6）的应用内更新仍会撞同样的 `EBUSY`**：
  这几版的 `app.asar` 里还是旧逻辑，本版修复只对 1.0.7 及之后生效。请按下面的
  「升级方式」手动升一次；从 1.0.7 开始，后续版本才能正常走「下载 → 重启 →
  自动换新版本」。
- **1.0.0 旧版**内置的还是更早的更新公钥，首次仍需手动更新一次。

## 升级方式

- **1.0.5、1.0.6（以及更早）**：手动升一次 —— 完全退出应用（托盘退出，任务
  管理器确认没有 `OPC Agent` 进程），用本 Release 的
  `OPC-Agent-1.0.7-x64-full.zip` 解压覆盖安装目录即可；也可以只把
  `resources/app.asar` 换成 Release 里的 `app-1.0.7.asar`（更省流量）。
- **到了 1.0.7 之后**：后续版本恢复应用内「检查更新 → 退出并重启」自动替换。
- 会话数据保存在 `%APPDATA%\opc-agent`，覆盖安装不受影响。
