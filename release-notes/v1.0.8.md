# OPC Agent v1.0.8

本版把「更新状态」的生命周期收干净：失败红字会自愈、也能一键忽略，成功与失败
都不再留残渣。

## 修复

- **升级失败的红字不再常驻**：此前只要有过一次交接失败，更新卡片上的红字就一直
  挂着，哪怕你后来手动装了完整包、实际版本早就不在失败版本上了。现在启动时会拿
  「当前版本」和失败记录里的版本做比较：当前版本已经越过它，就自动判定为「已消
  解」，静默收起提示并清掉 `apply-state.json`；只有确实还停在失败版本上时才继续
  展示。
- **更新卡片新增「忽略」入口**：交接失败（`apply-failed`）或健康检查超时已回滚
  （`rollback`）时，可以直接点「忽略」，红字消失、状态文件同步清空。网络、验签、
  哈希这类错误不提供忽略 —— 它们重试一次就会重新出现，给了按钮只会让人误以为
  问题已经解决。
- **成功与失败都不留残渣**：两条路径现在走同一套清理口径，统一清掉暂存包
  （`.download` / `.part` / `.asar`）、`apply-state.json`、`apply-job.json`、
  `update-swap.cjs`、`health.json` 与 `app.asar.bak`，不会有旧补丁或旧备份被下
  一次更新误用。唯一允许短暂存在的是失败时留给你看的 `apply-state.json`，它会在
  上面两种情况下被清掉。

## 校验

- `verify:a176-update-swap` 扩到 **51 条全过**，新增两例：
  ① 失败记录里的版本 ≤ 当前版本 → 不展示，且 `apply-state.json` 被清理；
  ② 「忽略」路径可清除提示与状态文件。
- `verify:a171-update` **154 条全过**。

## 需要注意

- **1.0.5 及更早版本（包括 1.0.6）仍需手动升一次**：这几版内置的还是旧的交接
  逻辑。**1.0.7 起自动更新链路可用** —— 从 1.0.7 升到本版可以直接走应用内更新。
- **1.0.0 旧版**内置的还是更早的更新公钥，首次仍需手动更新一次。

## 升级方式

- **1.0.7**：设置 → 关于与隐私 → 检查更新 → 下载更新 → 退出并重启，走应用内
  自动替换即可。
- **1.0.5、1.0.6（以及更早）**：手动升一次 —— 完全退出应用（托盘退出，任务
  管理器确认没有 `OPC Agent` 进程），用本 Release 的
  `OPC-Agent-1.0.8-x64-full.zip` 解压覆盖安装目录即可；也可以只把
  `resources/app.asar` 换成 Release 里的 `app-1.0.8.asar`（更省流量）。
- **1.0.0 旧版**：内置公钥与当前签名不匹配，需先按上一条手动更新一次。
- 会话数据保存在 `%APPDATA%\opc-agent`，覆盖安装不受影响。
